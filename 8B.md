# 3. GARANTÍAS DE 6B QUE NO PUEDEN ROMPERSE

La nueva ingesta DEBE respetar estas garantías ya verificadas.

## I1 — Canonical

```text
0 canonical → no translation
1 canonical → translation válida
2+ canonical → integrity violation
```

Nunca seleccionar silenciosamente una traducción.

---

## I2 — Directionality

Una relación:

```text
A → B
```

NO implica:

```text
B → A
```

Nunca generar automáticamente relaciones inversas.

Si existe evidencia inversa, debe existir como evidencia explícita.

---

## I3 — Provenance

Dos fuentes diferentes que producen el mismo texto destino:

```text
Source A → "perro"
Source B → "perro"
```

NO deben colapsarse como una sola evidencia.

La proveniencia pertenece a la evidencia.

El dedup de presentación no debe destruir provenance.

---

## I4 — Variant isolation

Nunca mezclar:

```text
LanguageVariant A
LanguageVariant B
```

porque comparten:

```text
CanonicalForm
```

La identidad real de la variante debe mantenerse mediante su ID estable.

Nunca elegir arbitrariamente una variante cuando el nombre sea ambiguo.

---

## I5 — Dataset reproducibility

Toda evidencia debe poder reconstruirse mediante:

```text
CatalogVersionId
+
corpus/source
+
lexical evidence
```

No depender únicamente de:

```text
latest Completed CatalogVersion
```

cuando el dato pueda quedar ligado a una versión concreta.

La ingesta debe dejar explícita la versión a la que pertenece.

---

## I6 — Completed versions are immutable

Una vez que:

```text
CatalogVersion.ImportStatus = Completed
```

no se debe modificar silenciosamente su evidencia.

Los triggers existentes son parte de la garantía.

NO desactivarlos para hacer funcionar la ingesta.

# 5. INGESTA DEBE SER CONTROLADA

No implementar un:

```text
INSERT ALL
```

sin validación.

Cada registro debe pasar por validación.

Como mínimo comprobar:

* CatalogVersion;
* LanguageVariant;
* Source;
* forma léxica;
* significado;
* idioma;
* dirección;
* provenance;
* verification status;
* canonical status cuando aplique.

Los registros inválidos deben producir un resultado explícito:

```text
Accepted
Rejected
Quarantined
```

No perder registros silenciosamente.

---

# 6. IDEMPOTENCIA

Ejecutar dos veces el mismo corpus sobre la misma versión NO debe duplicar evidencia accidentalmente.

Definir una identidad determinista de ingestión.

La identidad debe considerar los campos que realmente distinguen evidencia.

No usar solamente:

```text
CanonicalForm
```

como clave global.

La misma forma puede existir:

* en distintas variantes;
* con distintos significados;
* en distintas fuentes;
* en distintas versiones.

---

# 7. ORIGINAL VS NORMALIZED

No destruir el texto original.

Si existe normalización:

```text
OriginalForm
NormalizedForm
SearchKey
```

deben tener responsabilidades diferentes.

La normalización no debe convertirse automáticamente en autoridad lingüística.

No alterar el texto documental original únicamente para facilitar búsquedas.

---

# 8. VERIFICATION STATUS

La ingesta no debe convertir automáticamente un registro en:

```text
Verified
```

solamente porque fue importado.

Importación y verificación son conceptos diferentes.

Mantener la semántica existente:

```text
Imported
Documented
Verified
CommunityVerified
AcademicVerified
...
```

según el modelo real del proyecto.

Si la fuente aporta evidencia suficiente para un estado concreto, conservar esa evidencia.

Si no, no elevar artificialmente el nivel.

---

# 9. CANONICAL

No usar:

```text
ORDER BY TargetText
LIMIT 1
```

para decidir canonical.

El orden alfabético solamente puede servir para presentación determinista.

No es autoridad lingüística.

Si la fuente proporciona autoridad canonical:

```text
IsCanonical = true
```

conservarla.

Si no existe autoridad:

no inventarla.

Si aparecen múltiples canonical:

**fallar con integridad explícita.**

---

# 10. RECONCILIACIÓN

La ingesta debe dejar trazabilidad suficiente para responder:

```text
¿De dónde salió este lexema?
¿De qué corpus?
¿De qué versión?
¿De qué variante?
¿Con qué evidencia?
¿Con qué estado de verificación?
¿Qué equivalencia generó?
```

No considerar terminada una ingesta si no puede responderse eso.

---

# 11. SEGURIDAD DE VERSIONES

Nunca modificar datos de una:

```text
CatalogVersion.Completed
```

para corregir un corpus.

La corrección debe producir una nueva versión.

Ejemplo:

```text
CatalogVersion 1
    ↓
Completed
    ↓
INMUTABLE

corrección
    ↓
CatalogVersion 2
    ↓
nuevo ingestion run
```
